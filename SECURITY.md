# Security and sensitive reports

Use GitHub private vulnerability reporting when it is enabled. If it is unavailable, ask a maintainer for a private channel using a short message with no sensitive details. Avoid posting credentials, exploit details, private logs, device identifiers or instrument images in public Issues or Discussions.

Report the affected revision, a minimal synthetic reproducer and the expected failure boundary. If a report concerns unexpected instrument commands or state changes, provide a redacted summary and preserve supporting evidence privately. This research repository provides a synthetic demonstration and has no supported hardware release.
